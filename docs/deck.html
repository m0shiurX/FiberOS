02 The problem

Most ISPs cannot see the network they built.

Physical fiber infrastructure — POPs, OLTs, splice closures, splitters, drop cables — usually lives in spreadsheets, paper site notes, or a technician's memory. When a fiber is cut, nobody can say who's affected without a truck roll and a phone tree.

Where is this asset?
Undocumented. Tribal knowledge, not a record.
What depends on it?
No impact analysis before a repair decision.
Who touched it last?
No audit trail — changes vanish into memory.
Can a field tech act on it?
No mobile workflow — updates happen back at the office, if at all.
03 The answer
ISP Network Operations Platform

One digital model, from the POP to the last meter of drop cable.

FiberOS maps and understands physical network relationships the way the network itself is built — as a connected graph, not a flat asset list. Five questions it answers on every screen:

  1. 01 Where is this network asset?
  2. 02 What is connected to it?
  3. 03 Which customer depends on it?
  4. 04 What happens if it fails?
  5. 05 Who changed it, and when?

05 Why this holds up

Built on decisions, not guesses.

Every choice below was made against the actual workload, not habit — logged in docs/tech-decisions.md so the plan can be defended, not just demoed.

NowPOC + MVP

A modular monolith, on purpose

Laravel + Vue 3 + Inertia over PostgreSQL/PostGIS, mapped with MapLibre. No Kubernetes, no microservices, no second language — until scale actually demands it.

LaravelVue 3Inertia.jsPostgreSQL + PostGISMapLibre GL
Phase 2FiberOS Monitor

Python owns device connectivity — because the workload says so

Polling OLTs and routers over SNMP/SSH is I/O-bound, not CPU-bound. At one instance per ISP, low-hundreds of devices, Python's asyncio ecosystem matches the job — Go's concurrency edge only pays off at carrier scale, which this product doesn't operate at.

FastAPINetmikopysnmpAPSchedulerRedis pub/subLaravel Reverb
Deployment

One instance per ISP — their data never leaves their network

Routers and OLTs sit on a private LAN a cloud server can't reach. A single on-prem Docker stack solves that directly, and keeps sensitive topology data on the client's own site.

Docker ComposePoetryoutbound-only updates
06 How it's delivered

Central services

  • Cloudflare Tunnel edge

A field technician's phone reaches the ISP's own instance through a stable HTTPS tunnel URL — no VPN client, no firewall change at the client site.

Licensing: signed token, phone-home over the same outbound channel, 7–14 day offline grace period — an internet outage never locks a technician out mid-fault.
